## 一、已知问题

| 问题 | 影响 | 现状 / 修法 |
|---|---|---|
| WorkBuddy 自己的界面探针读不到 | 它只能靠通知通道，通知不到就不知道它在等你 | `probe_uia.py` 实测它「退回主窗口、按钮 0 个」——渲染面类名和 Electron 不一样，要先补一条 `find_render_surface` 的分支 |
| DWM 玻璃依赖系统的「透明效果」开关 | 关掉后球的背景会变成不透明黑，比原来的灰框更显眼 | `patch_transparency()` 已带 `SetWindowRgn` 兜底，但只在 DWM 调用**返回失败**时触发；系统允许 glass 但视觉上没透的情况检测不到。可加一次「显示后采样四角」的自检，不透就自动退到裁剪 |
| DWM 玻璃会键掉纯黑 | 界面里出现 `#000000` 的元素会变透明 | 当前样式里没有纯黑。要写进贡献约定：新增颜色避开 `#000` |
| 面板圆角外的阴影被窗口边界裁掉 | 圆角外侧一圈阴影没了，看着略平 | 要么把窗口开大几像素留白给阴影（要同步改 `_place_panel` 的偏移），要么用 `SetWindowRgn` 裁圆角后让 CSS 阴影画在圆角内 |
| 首次启动偏慢 | 冷启动到界面出现约 2~4 秒 | 主要是 WebView2 初始化 + 本地 HTTP 服务。可以先显示球、再异步建面板（`build()` 里已经有 `hidden=True` 的底子） |
| 多显示器切换后位置错乱 | 拔掉外接屏后球可能落在屏幕外 | 启动时校验位置是否在当前屏幕范围内，不在就回落默认（和 `remember_ball_pos` 的合法性判断是同一类） |

## 二、优化点

**性能**

- 界面探针现在是固定 2.5s 一轮全量扫。可以只在「窗口可见且非最小化」时扫，
  最小化的一家直接跳过（一次查询 80ms，四个工具就是 320ms）。
- 图标每次都重新从 exe 抠。加一层磁盘缓存（按 exe 路径 + mtime 做 key），
  目前只在内存里按路径缓存。
- 扫描目前是同步的（实测 9~19ms，够快），但 UIA 探针线程和主循环之间没有背压，
  极端情况下会堆积。加一个「上一轮没跑完就跳过」的判断。

**稳定性**

- `refresh()` 里对后端的调用目前靠外层 `try` 兜住。可以更细：图标失败、通知失败不应
  影响状态判定，各自降级并在 `capabilities` 里如实反映。
- 通知库（SQLite）被别的进程锁住时会读失败。当前是静默跳过，可以加重试 + 退避。

**体验**

- 面板高度写死 492px（`PANEL_H`）。屏幕不够高时会被裁掉一截，现在只是把它压到
  上边缘。要么按屏高算一个最大高度让内容滚动，要么给面板做成可缩放。
- 右键菜单（刷新 / 全部已读 / 退出）在第一代 tkinter 版里有，这一版还没搬过来。
- 拖动阈值 4px 硬编码在 `web/app.js`（`Math.sqrt(dx*dx+dy*dy) < 4`），可以进配置。

## 三、功能拓展

按「先做哪个」排：

**小（几小时内）**

- **右键菜单**：刷新 / 全部标记已读 / 开机自启开关 / 退出。桥已经有 `set_config`，前端加个菜单即可。
- **全部已读**：`runtime` 里给个 `mark_all_read()`，清掉所有 unread 和 approvals。
- **自定义工具**：现在 `AGENTS` 写死在代码里。放到配置文件里（进程名 + 品牌色 + 是否开界面探针），
  `models.py` 做一次合并，这样不用改代码就能纳管新工具（比如 Cursor、Windsurf、Zed）。
- **CLI 子命令**：`--once` 已经有了，可以加 `--json`（给脚本用）、`--list`（列出纳管的工具）。

**中（一到两天）**

- **全局快捷键**：注册一个热键（比如 `Ctrl+Alt+A`）直接展开面板，不用瞄准球。
  Windows 上 `RegisterHotKey`，macOS 上走 Carbon 的 `RegisterEventHotKey`。
- **免打扰时段**：配置里加一段「几点到几点不出声、不弹面板」，只改球的颜色。
- **多显示器记忆**：按显示器记位置（`ballPos` 现在是一个坐标，改成按屏幕名/分辨率做 key）。
- **托盘图标**：现在只能靠球退出，加个托盘项更常规。pywebview 不带托盘，需要额外依赖
  （`pystray`，很小），或者用 Win32 的 `Shell_NotifyIcon` 自己写。

**大（需要专门做）**

- **macOS 后端**：接口已经切好，照 `host/macos/__init__.py` 顶部的待办清单填五块
  （窗口 / AX 探针 / 通知库 / 图标 / 杂项）。估计两天，主要时间在 AX 权限引导和通知库解析。
- **事件时间线**：不只看「现在谁在等你」，还记一条谁在几点等你等了多久，做个小列表。
  需要引入持久化（SQLite，或者一个 JSONL 追加文件）。
- **统计视图**：一天下来各工具的等待次数、等待时长——有数据才知道哪个工具最爱卡你。
  依赖上面那条。
- **插件化的状态源**：把「怎么知道一个工具在等你」抽象成可注册的 provider
  （通知 / UIA / 日志文件 / HTTP 轮询），让纳管新工具的成本降到写一个 provider。

## 四、分发

✅ **已做**，见 [`packaging.md`](packaging.md)。

```
python tools/build.py --clean --zip
  入口         agenthub/__main__.py
  需要打包     web/、assets/（都是 --add-data）、LICENSE
  要排除的     tkinter、numpy、PyQt、pytest、PIL、win32com
  实测体积     12 MB（Windows x64，onedir）
```

三个注意点：

1. **WebView2 Runtime 不能打进去**，它是系统的。Win11 自带；Win10 一般随 Edge
   装好了；没有的话引导去装（微软提供 Evergreen Bootstrapper，支持静默）。
2. 默认 **`--onedir`**，因为 `--onefile` 每次启动都要解压几百个文件到临时目录，
   慢 1~2 秒——常驻挂件的启动速度比少一个文件重要。
3. **打包后 `__main__.py` 不能用相对导入**：PyInstaller 把入口脚本当顶层模块执行，
   没有包上下文。已改成 try/except 双分支。

GitHub Actions（`.github/workflows/build.yml`）在每次 push 到 main 时自动构建
Windows x64、macOS arm64、macOS x64 三包，并覆盖发布到固定的 `latest` release。

剩下的两件事：

- **macOS 签名与公证**：现在 unsigned，别人下载后第一次启动要右键「打开」。
  要干净分发得走 Apple Developer。
- **安装包**：现在是 zip。Windows 可以套 NSIS / Inno Setup 做安装向导 +
  开机自启勾选项；macOS 做 dmg。
